라크무 독립 맵 편집기 — 0.5 지형·자원·시작 위치

0.5 변경 (현재, 아래 버전 기록보다 우선)
  지형 분류 순서: 언덕 → 입구 → 평지 타일. 네 테마의 로컬 JTL 이미지
  200종씩 대조한 외형 분류이며 실제 통행성/고도 판정은 아니다.
  긴 원시 견본 목록을 대표 가족으로 축소, 세부 타일 선택은 기본 숨김.
  같은 가족의 가장 많이 쓰인 완전한 5바이트 레코드를 대표로 사용한다.
  모든 원본 변형/내부 속성은 세부 목록에 보존. 우클릭 추출도 정확히 복원.
  자동 절벽 접합/입구 생성/통행 보장은 아직 미지원.
  플레이어 시작 위치: 섹션 1 = 8*33 팀 설정 + 인원수*24 플레이어 레코드.
  0040B106..134 로더 크기 확인; 0040B177/18A는 플레이어 레코드 +8/+6의
  uint16 Y/X를 0043A9F0에 전달한다. 헤더 +13의 인원수는 변경하지 않는다.
  지도 번호 표시, 플레이어 선택 후 클릭 이동, 번호 우클릭 선택, 실행 취소.
  좌표 경계/중복 검사와 저장 후 재파싱 검증. 좌표 4바이트 외 설정은 보호.
  새 빈 맵에서도 시작점 이동 가능. 게임 EXE나 원본 맵은 변경하지 않는다.
  실제 게임의 스폰/기지 생성 공간과 멀티플레이 검증은 별도 필요.
  배포: dist/map-editor-0.5/RhakMuMapEditor/RhakMuMapEditor.exe

0.4 변경
  자원 견본 목록을 위치별 레코드가 아닌 두 종류로 정리. 테마별 ID 유지.
  새 자원 수량 입력, 기존 자원량 수정, 우클릭으로 현재 수량 읽기 지원.
  1..1,000,000 정수 검증. 원본 크기·메타데이터 보호와 실행 취소 유지.
  새 빈 맵: 선택한 기본 맵의 크기/테마/인원/시작 위치/기본 설정 사용.
  지형을 한 타일로 초기화, 섹션 3 배치물/자원과 섹션 6 장식 목록 제거.
  자원 없이 시작해도 두 종류를 새로 배치 가능. 임의 크기 생성은 미지원.
  일반 멀티플레이 자원 로더 0040CDA4는 저장량을 무시하고 3000/5000 사용.
  resource_amount_patch.py는 해당 25바이트만 맵 +16 수량 읽기로 교체.
  확인된 설치본 SHA256에만 적용; 고해상도 시험본은 거부. 실행 중 거부,
  백업/원자적 교체/해제 지원. 설치본 자동 변경 없음, UI 명시 확인 후 적용.
  모든 참가자에게 같은 자원량 패치 필요. 실제 멀티플레이 검증은 미완료.
  13개 테스트 통과: 24맵 새 빈 맵/수량 저장, 비자원 보존, 렌더링,
  실제 x86 수량 push, 원상 복구 및 알 수 없는 바이너리 거부 포함.
  배포: dist/map-editor-0.4/RhakMuMapEditor/RhakMuMapEditor.exe

참조 비교
  사용자가 지정한 WangGun_Win_221105/MapEditor.exe의 파일 필터는 *.wgm.
  제공된 왕건 샘플 WGM 시작 바이트 01 01 02 00, 라크무 RKM은 J2M\0.
  같은 엔진이라는 이유로 파일을 직접 호환하거나 확장자만 변경하지 않는다.
  왕건 MapEditor.exe UI 실행 및 도움말 전체 분석은 아직 하지 않았다.

라크무 로더 역분석 근거
  0040B030: 섹션 0에서 20바이트 헤더를 읽는다. +8,+10에 uint16 크기.
  0040B075/0040B088: 런타임 맵 크기는 헤더 크기에서 각각 4를 뺀다.
  0040B580: 섹션 2 지형. Y는 2씩, X는 8씩 증가한다.
  0040B5F6..0040B638: 각 위치에서 uint16 + byte + byte + byte (5바이트).
  0040B640..0040B6AA: Y%4가 2인 행은 X에 4를 더한다.
  0040B6F0: 지형 ID를 8x4 셀의 마스크에 따라 펼친다.
  따라서 지형 레코드 수는 ceil(width/8)*ceil(height/2).
  화면의 다이아몬드는 배치 순서를 표현하는 개략도이며 실제 텍스처가 아니다.
