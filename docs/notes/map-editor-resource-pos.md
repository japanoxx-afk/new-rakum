# 맵에디터 자원 위치 불일치 — 원인과 수정 (브랜치 map-editor-resource-pos, 커밋 6d4b93b, 워크트리 %USERPROFILE%\Documents\claud\rhakmu-respos)

## 원인
1. 좌표계: 게임은 지형 레코드(col,row)로 칸 X..X+7, Y..Y+3을 덮는다(X=col*8+(row&1)*4, Y=row*2; 0040B6F0, 다리 0040BDD0).
   오브젝트·시작 위치는 그 칸 격자의 픽셀 (x*32, y*32)에 놓인다(00439E60). 웹 에디터는 지형 다이아몬드 중심을 (X*32, Y*32)에 그려서
   자원·장식물·시작 위치가 게임보다 오른쪽으로 4칸, 아래로 2칸 밀려 보였다.
   - 근거: 원본 맵 24개, 자원 545개를 게임 통행 격자(JTL 속성, 0040B800)에 놓으면 모두 통행 가능 칸이다. 에디터 기준으로는 48개가 막힌 칸이거나 맵 밖이다.
   - 장식물은 게임 기준 1815/1963개, 에디터 기준 1145개가 통행 가능 칸이다. 시작 위치 7x7 영역은 게임 기준 120/120개가 모두 통행 가능하다.
   - 사용자 맵 Download\[4](N4) 냐이의 영광: 에디터 기준으로는 자원 23개 중 막힌 칸이 0개, 게임 기준으로는 5개다. 사용자가 본 증상과 일치한다.
2. 스프라이트: tiles/*_OBJ.js의 ox/oy가 BLD dx/dy만 쓰고 S16 프레임 left/top을 빠뜨렸다(자원 2~6px, 나무는 최대 84px 어긋남).

## 수정
- core.js: cellX/cellY/worldCell을 추가했다(CELL_OX=-128, CELL_OY=-64). cellBuildable/cellWater를 게임 칸 기준으로 바꿨다.
- app.js: 자원·장식물·시작 위치의 그리기, 클릭, 배치, 미니맵, 맵 경계선, 상태 칸 좌표를 바꿨다. kind 3(다리/입구)은 원본 맵 템플릿 기준이라 그대로 두었다.
- tools/obj_offsets.py로 OBJ.js의 ox/oy를 다시 계산했다(dx+left, dy+top).
- 파일에 저장되는 좌표는 바뀌지 않는다. 27개 맵을 웹 에디터 parse→serialize로 왕복해 바이트가 일치함을 확인했다(브라우저).

## 후속
- map_preview.py(런처 맵 미리보기)도 같은 규칙으로 그려서 같은 오차가 있다. 이 작업에서는 고치지 않았다.
- 실제 게임 화면에서는 확인하지 않았다.
