# 게임 화면 리플레이 — 4분대부터 유닛이 멈추는 문제 (v0.9073, 브랜치 launcher-v0.9073-replay-continue, 커밋 80e0d8b)

## 증상의 정체
- 재생기(replay_record_patch.py "feed")는 검사값(rand·유닛 해시·유닛 수)이 한 번이라도 다르면 그 뒤 기록 명령을 전부 버렸다.
  화면에서는 유닛이 멈춘 것처럼 보인다.
- 20261121_205441: 5225프레임 = 2분 54초 (대전 30프레임/초). 최신 20261122_003815(냐이의 영광)은 실제 게임 재생으로만
  어긋남 시점을 알 수 있다 (사용자 허락 필요). 사용자가 말한 "4분대"는 이 리플레이일 가능성이 크다.

## v0.9073 변경
- 어긋난 뒤에도 명령을 계속 재생한다.
- 어긋난 뒤에는 선택 명령(0x4002: [u16 0x4002][u16 길이][u8 개수][u16 id...])에서 유닛 주인(유닛+0x10 바이트)이
  명령한 플레이어가 아닌 id 를 0(빈 칸, 할당기는 1부터 씀)으로 바꾼다. 게임의 명령 처리(0x4407E0)는 주인을 검사하지 않는다.
- 배속 키 코드는 새 루틴 "keys"(0xB80)로 옮겼다 (feed 자리 부족). 이전 코드는 LEGACY(v0.9065~v0.9072)에 추가.
- 남은 위험: 같은 플레이어의 다른 종류 유닛이 그 칸을 쓰면 엉뚱한 명령이 간다 (예전 주석: 튕김 가능). 실제 게임 확인 필요.

## 근본 원인 단서 (205441)

  그 칸은 6001 전에 새 버서커(hp 220, 다른 위치)가 다시 썼고, 5226의 곰(101)은 칸 44를 받았다.
- 재생에서는 4528에 바로 죽음 처리(인구 감소, 죽은 프레임 기록)가 돼 5226(698 ≥ 600)에 칸 19가 재사용됐다.
  원래 경기는 인구가 18로 남아 있었다. 즉 죽음 처리(0x43c0a0, 죽은 프레임 +0x24)가 원래 경기에서 늦었다.
- 해시는 hp>0 유닛의 hp·위치·종류만 본다. 명령(+6), 애니메이션 등은 보지 않아서, 실제 어긋남은 5225보다 이를 수 있다.
